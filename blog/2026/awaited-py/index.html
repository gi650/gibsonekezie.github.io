Let’s start by differentiating synchronous code execution from asynchronous code execution

Difference between Synchronous Code Execution and Asynchronous Code Execution

I want you to think of the difference this way, synchronous code execution is the basic python code execution we are familiar with. This means code executes in a strict sequence and the running code blocks everything else until completion (blocking behavior);

Example of Basic Python Function (Synchronous Code)

When you call the function you just created, it executes the print function;

While for asynchronous code execution .. ? You guessed correctly! Asynchronous code execution does the opposite. It initiates tasks and continues without waiting for completion.

The Goal of Asyncio

Asyncio is a standard library framework for writing concurrent code in python. The main function of asyncio is to maximize usage of a single thread by handling I/O asynchronously and enabling concurrent code execution using coroutines. Another way to think of it is asyncio pads the gaps in a running thread with other concurrent tasks.

Now if you take a min to digest what you just read about a asyncio; you’ll come up with similar questions like How ? How does asyncio perform this ? what powers the asyncio framework ? This simple answer to both questions is EVENT LOOP

Event Loop

The event loop is the engine inside asyncio that runs and schedules tasks. It contains a collection of jobs to be run. You can think of the collection of jobs as a queue where jobs are added by you and some by asyncio. Then the jobs are processed one at a time but not always in order(If have you expertise in AWS this should remind you of the Amazon SQS standard queue != FIFO). The event loop takes a job from it’s collection of jobs, invokes it then gives it control (similar to a calling a function). Then the job runs, once it pauses or stops it gives control back to the event loop. In football terms, the Event loop is the Messi in your team, he gives you the ball to do your tomfoolery then you return the ball to him to make the play. This process continues indefinitely until there are no more jobs and the event loop is smart enough to rest and avoid wasting resources. The event loop will resume once there are more jobs to run. I know what you’re thinking, all this attributes sounds a little bit too familiar what if your AI agent runtime is just one smartass event loop ? you’re probably right

NOTE: Effective execution still relies on jobs sharing well and cooperating, a greedy job could easily hog control and leave other jobs to starve. Control doesn’t always get ceded back to event loop but I’ll touch more on that in the coming sections.

Async Function

I want us to cover the basic tenants of the laws that govern an async function:

  • It is defined using async def and can await expressions.
  • It cannot be called directly from the async.run function. (async.run function is how you execute async code)
  • Async function is a function that creates coroutines when called.

Coroutines

  • Object created by calling an async function.
  • Can be called directly from the async.run function.
  • Can be run only once.
  • Is an awaitable object.

Interesting Side Notes about Coroutine: The clear distinction between coroutine object (synonymous to coroutine) and coroutine function

Term What it is How you get it How you inspect it Lifecycle
Coroutine function An async def function definition Write async def work(): … inspect.iscoroutinefunction(work) -> True Reusable callable; called many times
Coroutine object A pauseable execution frame/object Call coro = work() inspect.iscoroutine(coro) -> True. Single-use; must be awaited or scheduled

Coroutines evolve from generators. Similar to coroutines functions, calling a generator function does not run it, it generates a generator object. Yield expressions and statements are only used when defining generator functions and are only in the body of a generator function. From this you can infer that the difference between a regular function and a generator function is the presence of yield expressions. If you yield directly within a coroutine function the coroutine function becomes an async generator function. “Yield from” is not allowed in coroutines, it creates a syntax error.

For more information on the history of coroutines I suggest you check out Lukasz Langa’s video from EdgeDB Import Asyncio

Task

Task is a coroutine(not a coroutine function) tied to the event loop. A task also maintains a list of callbacks functions. Creating a task automatically schedules it for execution by adding a callback to run it, in the event loop’s (*Collection of jobs). This is the recommended way to create a task:

asyncio.create_task()

A good way to think of a task is to identify it as a wrapper for coroutines. Remember a task itself is not added to the event loop only a callback to the task is added.

Await

Can be used either as an awaited task or an awaited coroutine. For awaited task, the awaited task adds a callback of the original task or coroutine to the event loop. For awaited coroutine, unlike the awaited task the behavior of the awaited coroutine is effectively the same as calling a regular synchronous python function (Remember when I told you that not all jobs cede control back to the event loop).

Best when.. You genuinely need the result before moving on. You want work to start now and collect the result later
  1. Awaited Coroutine (await coro()) — Runs One After Another step_two() doesn’t even start until step_one() finishes.
import asyncio


async def step_one():
  print("Step 1: start")
  await asyncio.sleep(1)
  print("Step 1: done")


async def step_two():
  print("Step 2: start")
  await asyncio.sleep(1)
  print("Step 2: done")


async def main():
  await step_one()  # Waits ~1s before moving on
  await step_two()  # Starts after step_one, waits ~1s


asyncio.run(main())

Output

Step 1: start
Step 1: done
Step 2: start
Step 2: done
  1. Awaited Task (await task) — Starts Immediately, Waits Later create_task() queues both right away, await asyncio.sleep(0) lets them begin, and await on each task waits for their results.
import asyncio


async def step_one():
  print("Step 1: start")
  await asyncio.sleep(1)
  print("Step 1: done")


async def step_two():
  print("Step 2: start")
  await asyncio.sleep(1)
  print("Step 2: done")


async def main():
  t1 = asyncio.create_task(step_one())
  t2 = asyncio.create_task(step_two())

  await asyncio.sleep(0)  # Let both tasks start on the loop

  await t1  # Wait for t1
  await t2  # Wait for t2


asyncio.run(main())

Output

Step 1: start
Step 2: start
Step 1: done
Step 2: done

Futures

low-level Object meant to represent a computational status and result yet to come. (does not perform the actual computation, just the result of the computation). Future can be easily infer from its name as a placeholder for result or status we don’t have yet. Future has a state attribute that can be pending, cancelled or done. You can easily relate future to a traffic light. Future transitions to either finished with a result or finished with an exception.Future can be used directly to make your own custom conditions for waiting and resuming.

Interesting Side Note It is actually the future class that implements the logic of storing callbacks referenced in task. The task just inherits it. Asyncio.Task subclasses asyncio.Future in other to gain these capabilities.

Async Code Support

Async code support are async features for async programming like async with, async for and async generators

Async with

async with is the asynchronous context manager (the async version of with). It awaits setup (aenter) when entering the block and awaits cleanup (aexit) when exiting—even if an exception occurs.

Why use it: Safely manage resources whose opening or closing involves async I/O, such as HTTP sessions, database connections, locks, or async file handles.

Key detail: Must be used inside an async def function, and the object must implement aenter and aexit.

Async for

async for is the asynchronous loop used to iterate over an async iterable (such as an async generator). At each step, it awaits the next item so the event loop can run other tasks while waiting.

Why use it: Process items as they arrive asynchronously without blocking the event loop.

Key detail: Must be used inside an async def function.

Async Generators( The Big Bad Wolf)

A function that looks like a coroutine but contains yield expressions. An async generator is a function defined with async def that uses yield instead of return. Calling it returns an async generator object that can await async operations between yielding values.

Why use it: Stream items lazily over time (like paginated API responses, log lines, or WebSocket messages) without waiting for—or loading—the entire dataset upfront.

Key detail: Unlike regular generators, you don’t advance them with next()—you consume them with async for (or anext()).
